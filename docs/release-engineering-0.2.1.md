# 0.2.1 交付工程记录

本轮继续改进本地、单人使用的文书与论证审查工作台：扩展实际文档解析能力，
减少输入丢失，完善异常恢复和安装验收。模型仍由用户选择，审查结果与修改仍由人
确认。当前保留 **experimental preview** 标识，本记录不声明产品已完成商业发行验收。

本文补充 [0.2 交付记录](release-engineering-0.2.md)。前一份记录中的测试数量、
时间和构建结果属于当时版本；本轮最终完整回归及发行验收结果见文末记录。

## 文档、编码与八种语言

本轮文本解析覆盖英文、简体中文、繁体中文、德语、法语、日语、俄语和拉丁语。
测试样本包含混合语言、重音字母、`æ/œ`、长音符、日语假名和俄语西里尔字母。
原始文件字节与摘要继续保留，解码后的文本用于识别预览、定位和审查。

| 格式 | 本轮实现 | 边界 |
| --- | --- | --- |
| Markdown/TXT 及文本日志 | 自动或显式选择编码，记录实际编码及歧义候选 | 自动检测不能唯一判定所有旧编码；需要人工核对预览 |
| CSV/TSV | 正确处理引号、分隔符和多行单元格，记录稳定行列定位 | 不执行公式，不重建电子表格样式 |
| HTML/HTM | 标题、段落、列表和表格正文；忽略脚本、样式、模板及可识别的隐藏内容 | 不执行脚本、不获取外部资源；不等于完整浏览器/CSS 渲染 |
| RTF | 控制字、分组、Unicode 回退、代码页与十六进制字节 | 嵌入图片/对象和不支持的内容明确警告；复杂表格与排版不保证保留 |
| Word DOCX/DOCM、ODT | 从文档包提取正文及可用结构定位 | 宏不执行；图片、脚注、修订及复杂结构有明确提取限制 |
| Excel XLSX/XLSM | 工作表、单元格和隐藏状态；读取已保存公式缓存 | 不重算公式，不访问外部工作簿；缓存缺失或可能过期会提示 |
| PowerPoint PPTX/PPTM | 幻灯片文本、表格、备注及隐藏状态 | 不重建动画、交互、图表渲染和视觉布局 |
| DOC/WPS/XLS/ET/PPT/DPS | 根据内部结构识别伪装扩展名；真正的旧二进制文件交由本机 LibreOffice 转换 | 当前环境尚未完成真正二进制 Office/WPS 的实际转换验收 |

Unicode 文件支持 UTF-8、UTF-16 和 UTF-32，包括字节序标记与显式字节序。
常用旧编码选项包括 GB18030/GBK、Big5、Windows-1252、ISO-8859-1/15、
Shift-JIS/Windows-932、EUC-JP、ISO-2022-JP、Windows-1251、KOI8-R 和 ISO-8859-5。
显式选择优先；HTML 可使用文件声明的 charset，RTF 另按自身字体/代码页控制处理。
解码不会靠静默丢字或替换无法解码的字节来假装成功。

文书工作流会显示歧义和候选，用户可换编码后重新识别。旧研究 IR 初始化/导入
新版本遇到自动解码歧义时直接拒绝，要求显式选择后重试，以免把不确定文本绑定为原稿。

**文本可解析不等于八种语言的模型审查质量已经得到保证。** 本地预检只覆盖有限
词项和结构规则；八种语言的论证、事实、引用与专业判断仍需独立模型及具备相应
语言能力的人核验。本轮没有把文本字符保留测试计为语义审查质量验证。

文本 PDF 可使用包内/可选 PDF 适配器。扫描 PDF 则需要本机 PDF 渲染组件、
Tesseract 和每个选中的语言包；支持选择 `eng`、`chi_sim`、`chi_tra`、`deu`、
`fra`、`jpn`、`rus`、`lat` 及组合，默认 `chi_sim+chi_tra+eng`。
缺少组件或语言包会显示诊断。语言选项出现不代表已安装，也不构成 OCR 准确率承诺。

## 界面、流程与草稿

- 主界面默认繁體中文，可切换 English；偏好保存在本机，服务重启或浏览器刷新后
  可恢复。只翻译界面文字与明确的系统标签，原文、文件名、证据和用户输入不翻译。
  含文件名或用户内容的服务诊断保留原始文字，收在操作详情中。
- 七步流程条与“繼續 / Continue”按钮可以跳到所需操作，必要时展开折叠内容。
  没有发现问题时，人工裁决和修改步骤不阻挡结果导出；审查范围仍写入审计记录。
- 表单草稿按项目、有效文档和版本保存；AI 响应另按任务绑定，修改输入按操作决定
  绑定。切任务、项目和文档版本不会把其他上下文的草稿带入当前操作。
- 界面语言切换保留上传前选中的文件、标题、编码和已有表单内容；预检维度的
  勾选在切语言和运行后保持。刷新上传前页面仍需重新选择文件，这是浏览器文件控件
  的行为，不能把它与已导入项目的本机草稿混为一谈。
- 保存失败保留输入并支持重试/下载草稿；较旧页面的保存不能覆盖较新修订。
  未保存或正在保存时会触发离开提醒。退出期间先禁止继续编辑，保存成功后才关闭
  服务；保存失败则保留可恢复的页面。
- 对已定义请求收据的写操作，响应中断会以同一编号和内容重试一次；已提交结果
  被复用，避免重复审计记录。同编号不同内容被拒绝。仍无法确认时重新读取项目状态，
  不显示为已确定成功。

研究兼容视图及专业论证视图也已改为繁體中文/English，语言切换保留裁决弹窗、输入和版本选择。报告已保存但提示准备失败时，可以通过明确的继续按钮重试；提示写入失败会回滚该次准备，保留原报告。

研究兼容视图继续原位访问旧项目；格式与功能关系见
[统一工作台说明](unified-workbench.md)，不自动把旧研究库迁入文书库。

## 研究 IR、严格协议与崩溃恢复

新研究项目和导入的新版本在 `DocumentVersion.source.decoding` 中保存解码收据：
实际编码、用户请求的编码、UTF-8 文本摘要及歧义信息。原来的 `source.sha256`
继续绑定上传原始字节。验证时重新解码并核对文本摘要，避免原字节没有变化却用
另一种解释替换了论证文本。相同字节配合不同的明确解码可以作为有据可查的新版本。

既有 IR 版本没有解码收据时，仍按原来的 `utf-8-sig` 规则验证，不自动补填、迁移或
改写旧原稿。新请求使用 `argument-ir-extraction-v2` 提示：给出完整 JSON 字段、
允许值和关系端点规则，并强调主要 Claim、主要方法与支持链的准确抽取。
现有 v1 提示仍可按其原字节重建验证；提示版本变化不授权覆盖旧验证记录。

严格 JSON 入口拒绝非有限数、数值溢出、孤立代理字符和不合法字段类型。
无效 IR 会按其错误类型记录为不可用或可校正结果，保留原始响应；不会因错误的
relation 类型使校验器崩溃，也不会把布尔值当作合法 schema 版本。
这与文书 AI 导入中的“人工关联/严格回显”是不同契约：人工关联放宽的是任务回显
要求，不是对实质审查字段、定位或原文摘要的要求。

导入研究新版本使用与文书写入相同的恢复机制。原文件改写前保留旧字节，新建文件
和目录记录在事务范围内；版本目录已产生但历史索引尚未完成时，失败或中断不会
让半个新版本成为正式历史。下次打开遇到合法恢复日记会回滚并允许重试。
验证命令也可能在打开项目时完成这个恢复，因此遇到已有恢复日记时并非绝对只读；
没有日记的正常验证不会补收据或改写历史。

恢复会先验证所有恢复输入，再变更项目文件；损坏的恢复记录会报错并保留。
该机制应对本地进程中断和普通写入失败。摘要链仍是本地不一致检测机制，
不能对抗可同时重写全部原件、收据和索引的完整磁盘写入者，也不能代替独立介质备份。

旧命令行的 `prepare`、`prepare-track`、`run`、`run-track`、`quickstart` 和
`campaign` 也支持 `--encoding`。它们保留原始稿件字节与原摘要；执行器的提示和
报告传输继续使用 UTF-8。多轮 campaign 只读取一次稿件快照，执行期间修改外部原件
不会悄悄改变后续审查输入。

## 文书审查与续审协议

- 当前任务绑定有效文档、IR、上下文和审查轮次；新轮的预检、协议、导入和导出使用
  新稿，旧轮结果不再被计为当前 AI 任务完成。需要继续处理的历史问题仍保留来源。
- 模型引文和定位必须能在本轮稿件中核对，文档类型也必须一致。比较时允许合理空白
  和 Unicode 等价写法，原始证据文字照常归档。人工关联可以省略回显字段，但已回显
  的字段不能与实际请求冲突；外部复审新增问题也执行修订稿证据校验。
- 模型不能自行填写接受、拒绝或已解决等人工状态。零问题结果必须包含模型实际提供
  的检查范围说明。无效字段类型、错误数组及非有限 JSON 数值在写入前拒绝，避免把
  无法导出或绕过人工裁决的结果留入项目。

## Word 输出与交付文件

支持的 DOCX 净稿路径保留原包中未修改的样式、媒体和其他部件，应用已批准的
普通段落、连续段落和简单单元格修改。原生 Word 修订副本只覆盖受支持的文本替换。
涉及已有修订、域、书签、超链接、复杂单元格等内容时，保格式或原生修订路径可能
拒绝该修改。

保格式路径失败时，导出明确命名为 `规范化修改稿.docx` 或
`规范化本轮未修改稿.docx`，并在 `Word导出说明.md` 及能力记录中解释原因。
这种副本可能遗漏原图、页眉页脚和完整排版，需要与原件对照。
不能仅因文件可打开或 XML 验证通过，就声称已通过真实 Word 分页和视觉验收。

## 安装、升级和卸载

安装器核对严格发行清单与完整文件集，拒绝路径异常、链接、摘要错误和额外文件。
复制到同盘暂存目录后再次校验，再运行该副本的自检与升级检查；程序版本、
安装登记和快捷方式均有失败撤回路径。中断后的可验证暂存状态可在重试时恢复。
安装锁独立于项目写锁；同版本不同内容的包不会覆盖原安装。

`-InstallRoot`、`-ProjectRoot`、`-ShortcutRoot` 可用于隔离部署和回归；卸载可用
`-ConfirmRemoval` 明确选择非交互执行。卸载仅处理登记并校验通过的程序版本，
保留项目、备份及未登记内容。具体操作见 [便携版说明](portable-guide.md)。

自动升级前备份仅覆盖指定库直属的 `*.document-review-studio` 项目。
默认旧研究库、其他命名项目和未指定的自定义库都不在此范围内，不能将安装成功
描述为“所有研究材料均已备份”。这些目录应在关闭工作台后另行完整备份。

发行构建将程序、界面/协议资源、安装脚本、清单及归档放在完整版本目录内，
经过构建验证后整体发布。内置自检会实际读取打包界面、解析文本 PDF，并执行
项目审查及备份恢复流程。当前程序仍未做发行者代码签名，文件摘要不能证明发布者身份。
