# 文书与学术统一工作台

默认运行 `python critic_runner.py app`；`studio` 是同一入口的兼容别名。
可直接传入 Markdown、TXT、DOCX 或 PDF，仍需先由用户确认识别内容。

## 三条工作流与原始完成标准

首页先按这次要做的事选择入口。三条流程各自保留来源与决定，不会把一种项目
自动转换成另一种项目；“学术审查”也不自动生成完整论证图谱。

| 你的目标 | 从哪里开始 | 得到什么，以及原始标准的对应范围 |
| --- | --- | --- |
| 审查一份新稿 | 默认首页“新稿审查”，上传文档并确认识别、类型与上下文 | 文书/学术/综合审查、段落定位、接受/拒绝/暂缓、修改批准、版本复查和导出。覆盖导入、人工决定、修改稿及审计这些用户目标；使用统一文档项目的合同，不冒充原 Argument IR 图谱。 |
| 已有一份审查报告，按报告修改稿件 | 默认首页“已有审查报告，直接修稿”，在研究页面导入 Markdown/TXT 原稿并粘贴报告 | 报告原件归档→发现逐项确认→只针对接受项生成提案→逐项接受/拒绝/编辑/重新生成→不可变 V2→按原审查条件复查→人工结论与导出。对应原产品化基线的“稿件 + 既有报告”完整目标。 |
| 研究主张、证据、推理关系及跨版本变化 | 首页“专业论证图谱与历史项目”打开已有论证项目；新项目先用专业流程完成主张提取与确认，再打开专业视图 | 完整原 DoD 的 Claim/IR 修正、Rule/Perspective Lens、来源链、结构差异、人工 Lineage、原完整 Lens 复查、四维 Citation 和 Argument History。原 DoD 允许的非 JSON 命令行操作仍是该路径的一部分。 |

[0.2.2 要求审计](commercial-requirements-audit-0.2.2.md)。原作者 Gate A/B 通过记录
继续保留；三条路径存在、自动化通过，均不替代 Gate C 的真实作者对照任务。

## 共用流程

上传 → 确认识别 → 确认审查类型与上下文 → 本地预检 / 独立 AI 审查 →
人工裁决 → 明确操作类型与逐段批准 → 修改稿、原标准复查与导出。

文书、学术、综合模式共用原件存储、稳定定位、独立 Finding、修改计划、
Hunk 审批、外部复查、下一轮审查及 DOCX/Markdown/审计包导出。
不是把不同审查者的意见合并为一份共识，也不产生论文总分。

| 审查类型 | 默认独立维度 |
| --- | --- |
| 文书 | 表达、执行、合规筛查、治理、正式格式 |
| 学术 | 论证与反例、方法与可复现性、引用与证据 |
| 综合 | 上述八个维度；适合带研究论证的项目书等 |

审查类型、学科、研究类型属于不可变的已确认上下文。确认为文书的旧项目
继续按五个文书维度运行，不会被自动改成学术项目。若确需改变上下文，创建
新项目并重新确认；不要手改 `context.json`。同一文件在同一项目库会复用已有
项目，需要独立上下文时可使用不同文件名或另一个 `--data-dir`。

## 学术升级

- 论证：区分描述/因果/规范主张，追踪独立证据和推理桥梁，要求竞争解释、反例与适用边界。
- 方法：区分实证、理论、人文解释、综述和工程研究；本地规则按确认的研究类型路由，学科背景进入每份 AI 协议。
- 引用：区分来源存在、书目准确和支持归属主张。AI 声称 `verified` 时必须提供来源名、定位、URL/附件和适用说明；这些字段齐全也只是可审计的模型声明，不是自动事实认证。
- 本地预检：提示因果措辞、方法说明缺口、材料可获得性，以及单项数字引用与文献条目的缺失/重复。保留原文块定位和稳定 `check_id`，全部提示保持 `cannot-confirm`。
- 核验材料：上下文中可粘贴来源摘录、页码和说明，传入独立审查协议；仅填写 URL 或路径不会自动下载网页或读取文件。
- 修改复查：学术模型 Finding 与文书 Finding 使用同一批准/版本/复查链。复查绑定原始协议、请求和响应，模型建议解决后仍须人工确认；新发现继续进入下一轮。

本地文本匹配不是同行评审。即使本地复跑状态是 `resolved`，也仅表示同一
文本检查不再触发，不表示研究有效或引文真实。作者—年份、编号范围、脚注
引注等留给独立审查；系统不联网查文献、不编造 DOI、不运行实验、不验证
原始数据，也不要求公开受保护的研究数据。实际模型与真实用户验证仍单独记录。

## 旧项目与专业研究视图

统一首页展示旧 `.argument-workbench` 项目，点击后在同一个端口的
`/research/` 打开原流程，保留 Reviewed IR、Claim、Rule/Perspective Lens、
Citation、lineage 和 Resolution。页面提供返回统一工作台的链接。

默认继续使用原 DocumentReviewStudio 项目库并发现原 ArgumentWorkbench
项目库；显式 `--data-dir` 则在同一目录中发现两种项目。`app --project PATH`
可直接打开两类已有项目，不复制、不覆盖、不自动迁移底层存储格式。
新统一学术项目不会自动生成 Reviewed IR；图谱研究仍属于保留的专业流程。
旧 `app MANUSCRIPT --project DESTINATION` 的显式 Markdown/TXT V1 导入语义
保留，普通新文档导入请用 `app FILE --data-dir LIBRARY`。

## 验证边界

本节记录统一入口最初实现时的验证。0.2 新增交付验证见
[交付工程记录](release-engineering-0.2.md)；其中浏览器全流程、Word 输出与 CLI
能力已扩展，下面的历史限制不代表当前全部功能。

新增回归覆盖审查类型路由、旧上下文兼容、方法分型、引用定位与核验字段、
AI 审查到人工复查导出闭环、共用服务器鉴权和项目隔离。PDF/OCR 仍是可选
适配器，DOCX 导出仍是规范化修改稿，不是原位 Word 修订。当前仍为实验预览。

本轮本地验证（Windows / Python 3.14）：

- 完整回归：331 项测试，全部通过，4 项按环境条件跳过；新增 9 项统一/学术回归。
- 浏览器脚本语法检查通过；本机 HTTP 测试验证两套项目状态隔离、鉴权、路径拒绝和兼容路由。
- 构建并安装 wheel 后，在项目目录外以 `python -I` 验证模块、协议资源、文书/学术流程和统一服务器，全部通过。
- 实际页面只读检查确认统一标题、原文预览与流程条正常出现。浏览器安全审查拒绝了测试项目的“确认识别”点击，未绕过；完整浏览器点击链尚未验证。
- AI 响应和人工决定均使用自动化测试夹具；不是实际模型实验或真实用户验收。真人产物按用户要求暂缓。
