# 0.2.11 · 文本原文位置与表格行号

此前文本解析将每次换行都计为一个字符。Windows CRLF 实际占两个字符，导致
后续段落的 `char_start`／`char_end` 逐行偏早；表格之后的段落也受影响。
现在保留实际换行长度，位置对应解码后的原文 Unicode 码点范围，终点不包含在内，
不是字节偏移或 UTF-16 代码单元。编码标记由文本解码层处理，不计入正文位置。
范围仍覆盖整条原始行，包含 Markdown 标记和行首尾空白，不包含换行符。

Markdown 表格跳过分隔线时，此前把数据行索引误当成连续的原文行索引。
现在每一行单独保留原始行号，单元格属性与 source-map 使用同一真实行号。
表格的行列坐标及文本块标识生成规则不变。

新文本解析结果增加 `source_location_version: 2`、字符范围依据和单位说明。
已有项目的结构化文档与审查回执不会自动重写；新导入或获准重新识别的稿件采用
修复后的定位。历史审查的哈希绑定继续对应当时保存的材料。

回归覆盖六种换行、UTF-8／UTF-16／UTF-32、emoji、多语言、首尾空白、混合换行、
无末尾换行及 Markdown 表格。测试使用定位范围反向切取原文，核对真实文本与行号。
这是确定性证据定位修复，不是模型语义审查准确率的评测。
