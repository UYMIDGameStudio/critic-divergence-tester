# 0.2.19 · 批准修订后的条目归属

此前删除 HTML 条目的首段后，剩余续文仍被标作续文，导出因而丢失编号；将条目
正文替换为多个段落时，新生成段落只记录拆分来源，没有继承条目身份，影响后续
界面提示和审查对段落归属的理解。

现在只对经过批准的修订结果计算条目首段。删除一个段落不等于删除整个条目，
剩余第一个有正文的片段保留原编号；空段落不消耗这个位置。若剩余片段是标题，
保留标题类型与层级。拆分与范围替换的新段落继承原条目的语义属性；Markdown
列表需要拆分时，为其建立稳定的共享条目身份，不猜测新编号。

新生成内容保留 `generated` 来源和批准动作绑定，不继承原段落的行号等原文坐标。
独立插入／追加段落不自动继承条目归属。原始 IR、人工决定和旧修订产物不会重写，
拒绝的修改不进入新稿；后续条目保留原有编号，不擅自重新编号。

完成 93 项修订、逐项批准、复审协议及 Word 回归；随后补充空段落边界并复测
全部 8 项条目修订用例，均通过。测试经过实际项目创建、人工选择操作、Hunk 批准、
不可变新稿生成和正式 Word 导出，同时核对原始 IR 字节及项目完整性。

本次保持既有段落编辑合同，不新增整项删除或自动重排列表的操作。产品仍为
experimental preview；这些工程验证不代表模型语义审查或外部作者试用已经通过。
