# 0.2.20 · 修订来源映射与复审定位

此前修订稿直接继承旧稿的 `source_to_block`，导致已删除段落仍出现在映射中，
新生成段落却没有映射。同时外部复审要求新增问题引用当前段落 ID，协议却只提供
修改稿 Markdown 和历史协议；模型无法从这些材料获知新增段落的准确 ID。

现在每次生成批准修订时，按当前段落重建来源映射：保留段落指向父版本锚点，
记录正文是否相对父版本变化；新增段落明确标为生成内容，并保留批准动作及拆分
来源，不捏造原稿行号或字符范围。删除段落不进入当前映射。表格和单元格也纳入
当前映射范围。父版本 IR 的路径与 SHA-256 被明确记录，并加入审计父关系。

位置仍是历史锚点或生成段落标识，不重新声称为修订后 Markdown 的物理偏移。
修订元数据使用 `revision-provenance-v1` 来源映射合同和定位版本 3，并明确
`character_offset_basis=historical-parent-document`。历史 IR 与旧协议保持不变。

独立审查、对抗审查和外部复审采用一致的定位说明：当前引文取自当前 `block.text`，
旧稿位置不证明修改后的文字曾出现在原文件。外部复审现在直接提供完整的当前
结构块与定位，包含生成段落；取消同时重复附上同一份新稿 Markdown，保留原始
批评协议快照与旧问题作为历史证据。

25 项专项测试与 128 项相关回归通过，并另行复核两条对抗协议路径。新增流程
测试只从导出的复审协议读取生成段落 ID、正文和定位，成功提交对应新增问题，
随后验证项目完整性；来源映射测试同时核对删除、拆分、表格、生成内容和父文件哈希。

定位可验证不等于批评在语义上正确。产品仍为 experimental preview，外部作者
试用及模型质量评估继续保留原有验收边界。
