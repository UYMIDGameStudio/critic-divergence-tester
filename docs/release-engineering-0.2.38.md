# 0.2.38：引文上下文与局部截取提示

## 字符出现与论据成立

现有引文核对证明指定文本块包含连续字符，不证明这些字符支持批评。例如 `can` 是
`cannot` 的一部分，`5%` 是 `15%` 的一部分；`approved` 可以同时出现在肯定和否定、
不同说话者的语境中。若只看单独的证据字段，可能误读原文。

本版为 Finding 的主引文增加来源上下文预览，标亮实际匹配片段。对词语、复合表达或
数字内部的局部截取、同块多次出现，以及仅含不可见字符的引文给出提示。
片段提示不自动裁定批评，也不禁止合法的词法或字符研究；请核对完整表达和作者立场。
细读、综合审查与对抗阶段原有的引文校验仍保留，本版没有声称对所有次级引文都增加了
同样的上下文面板，或已实现语义核验。

## 显示与有界工作量

每条主引文最多显示3个上下文，每侧最多96个字符，匹配片段预览最多240个字符。
扫描计入重叠位置，在第129个匹配处停止，并明确标记计数并非精确总数。若较晚出现
局部截取，优先保留一处相应预览，避免提示风险却只展示正常位置。这不是穷尽查找。

预览沿用既有的 NFC 与空白归一化，原始文件、IR 文字及引文原字段不改写。显示内容
可能合并换行或使用等价字符，明确标记为预览；不生成或冒充原始字节、原稿字符位置，
也不能将预览当作自动修改锚点。NFC 的定义见
[Python unicodedata 文档](https://docs.python.org/3/library/unicodedata.html)。

局部词语提示是有限启发式，不是完整分词器，不声明符合 Unicode 文本切分算法。
对中文、日文等不强行套用空格分词边界；例如「不可能」中的「可能」仍展示完整上下文，
不会单凭字符邻接自动判错。可靠分词需要语言相关机制，参见
[Unicode UAX #29](https://www.unicode.org/reports/tr29/tr29-49.html)。
其他未被提示的引文也不因此获得“无断章取义”的认证。

同一次投影对被引用的文本块只归一化一次；缓存只在当前调用内存在，不保留跨项目或
跨操作的稿件缓存。预览大小和匹配扫描均有界，避免大量重复字符膨胀响应。

## 协议、导出与历史

新审查请求要求完整保留词语、复合表达、数值、否定、范围及归属，并说明字符出现不足
以支持批评。原有响应字段与引文匹配语义不变，已保存请求继续使用原快照。
升级不会因新的提示规则重判历史结果，也不会把提示升级成人工批准。

新视图与导出报告在 `verification_context[Finding ID].source_quote_review` 中记录
版本、匹配状态、数量是否精确、选定上下文、提示类型和显示依据，并明确
`advisory_only: true`、`semantic_accuracy: not-established`。这些是应用从本次绑定的
IR 派生的辅助数据，未混入原 Finding、模型原始响应或旧 AuditRun。
来源可用时，记录同时绑定文档标识、块标识和未经归一化的块文字 SHA-256，避免把同一块标识误当作
跨修订保持相同文字的证明；正式产物的收据继续绑定完整 IR。
AI 快照与正式审查报告均携带这些上下文，历史文件不自动重写。

网页中的所有原文片段仍作普通文字转义；新 Markdown 上下文区使用缩进代码块，避免
文档中的 HTML 或反引号在该区成为活动标记。

## 验证

对照既有匹配实现验证300组固定随机 Unicode 样例及明确边界，保持空白、NFC、外层
引号与连续片段行为一致。定向样例覆盖八种语言、词缀、数字、负号、小数、千位分隔、
连字符、撇号、重叠、重复位置、较晚的局部匹配、不可见字符和容量上限。

真实项目测试核对页面、AI 快照和正式报告中的上下文，确认模型 AuditRun 与原件字节
不变。浏览器检查繁中桌面、英文320宽度、局部匹配高亮、肯定与否定的重复语境、HTML
惰性、真实下载、人工裁决及正式导出。发行自检增加 `quote-context`。
这些测试验证匹配与呈现边界，不作为模型语义准确率或商业试用的验收结论。
