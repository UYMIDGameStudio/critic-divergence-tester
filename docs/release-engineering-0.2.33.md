# 0.2.33：Word 修订与未提取注释的可见范围

## 已复现的问题

旧识别器只检查正文中的插入、删除修订及追踪设置。移动修订可能把移动前后的文字
连在一起，却没有警告；段落格式等既有修订也未被标记。Word 导出已经拒绝其中一些
结构，导致识别与导出对同一原件给出不同判断。

只有尾注的文件也可能在未提取尾注正文时没有任何提示。此外，设置中明确关闭追踪
修订的值被误当作已启用；Word 解析没有执行已有的文本块数量限制。

## 修复

- 识别与原位 Word 导出共用修订标签集合，覆盖既有插入、删除、移动、移动范围以及
  段落、字符、节和表格属性修订。检查正文、页眉、页脚、脚注、尾注与批注部件，记录
  实际发现修订的部件和类型。范围以代码中的标签集合为准，不声称覆盖所有 OOXML 扩展。
- 原位 Word 导出重新检查原始 ZIP 的相关 XML，不仅信任旧识别记录中的布尔标志。
  这也保护历史记录中的漏检原件；程序不会自行接受或删除原件的修订。
- 明确关闭追踪的 `false`、`0`、`off` 按关闭处理；没有显式值的追踪元素仍按开启处理。
  实际存在的修订不因关闭追踪而忽略。现有拒绝已开启追踪的原位导出规则保留。
- 脚注、尾注的引用或正常注释内容触发高风险提示，分别记录部件是否存在、正文引用
  数量、注释数量及 `content_extracted=false`。只含分隔符的部件不虚构缺失正文。
  有引用却缺少部件时仍提示；不把包内文件缺失理解为文章没有注释。
- 这些限制进入确认界面、质量信号与保存的独立审查协议。普通确认被拦截，作者可以
  修正识别、换稿，或明确带警告继续；这不等于确认所有注释或未决修订均已被准确读取。
- Word 文本块（包括表格与单元格）执行 `max_text_blocks`，默认50000。超过上限时
  拒绝整个识别结果，保留上传字节和诊断，不交付残缺的内部文档。

修订语义参考 [Microsoft 的修订说明](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-accept-all-revisions-in-a-word-processing-document)，
尾注部件参考 [Microsoft Endnote 文档](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.endnote)。
这里采用的是识别和阻止误判的边界，未采用自动接受修订的处理流程。

## 版本与验证

本版仍未把脚注、尾注正文抽取为可引用的正文块，也不提供原位注释编辑。
不得把这些改动描述为“已经完整解析脚注与尾注”。原件和历史识别结果不重写；
需要新检查时重新解析为独立项目。Word 识别版本标为 `document-review-studio-docx-v2`，
文档存储、IR及模型响应契约不变。辅助 XML 损坏或含禁止的 DTD 时识别明确失败。

合成用例覆盖移动和范围标记、格式修订、辅助部件修订、关闭追踪、注释部件缺失、
分隔符对照、原协议可见范围、原件字节不变、旧识别重新解析与容量上限。
浏览器验证繁中桌面与英文窄屏的警告、普通确认拒绝、带警告继续及实际保存的学术请求。
发行自检同样运行这条 Word 确认和协议生成路径，不调用外部模型或读取真实稿件。

安装和升级见 [便携版说明](portable-guide.md)。
