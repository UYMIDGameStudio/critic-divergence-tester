# 0.2.7 · 删除中断与可恢复备份

删除项目时，程序先生成备份再写入删除标记。此前如果 Windows 拒绝移动项目目录，
项目会留在原地但不能编辑；后续备份还可能携带该标记，导致恢复的新项目同样不能编辑。
三个失败注入案例已分别复现这些问题。

- 新删除操作在移动失败时撤销自己创建的标记，原项目恢复可编辑，已完成的备份保留。
- 项目库锁覆盖整个删除过程；Windows 所需的项目文件锁仍在移动前释放。
- 新备份排除运行时删除标记；原项目若已处于中断删除状态，创建备份不会擅自恢复其编辑权限。
- 旧备份中的删除标记仍必须通过字节长度与哈希校验，但不带入恢复的新项目。
  被改写的标记和伪装为标记的目录不会绕过校验。
- 回归实际执行恢复后的编辑及删除重试，不只检查标记文件是否存在。

另修正一处 Windows 兼容性测试：指定任意目录的旧论证项目时，使用文件系统确认
同一目录，避免把 `RUNNER~1` 与长路径误判成不同项目。原断言仍要求打开指定项目。
此前远端 Python 3.10 / 3.14 的 690 项测试均已跑完，唯一失败均为这处路径断言；
这不是新版本全量通过的声明，新版本结果以相应提交的 CI 为准。

产品仍为 experimental preview；此修复不改变审查协议或人工判断权限。
