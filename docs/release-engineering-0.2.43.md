# 0.2.43：Word 注释与审查范围

## 实际问题与正文关系

此前 Word 脚注与尾注只产生「尚未提取」警告。即使作者在注释中给出了限定、
出处或反例，审查者也只能看到正文，不能核对这些材料。本版将可读注释作为独立
的来源块进入同一 IR，正文不拼接注释文本，引用关系另存于块属性。

Word 通过引用标记的 ID 关联注释部件中的相应条目；注释本身可以包含段落、表格和
内容控件。依据：[FootnoteReference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.footnotereference?view=openxml-3.0.1)、
[FootnoteEndnoteType](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.footnoteendnotetype?view=openxml-3.0.1)。
分隔线和续注分隔线有不同的类型，不能当作作者正文。
[Type 定义](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.footnoteendnotetype.type?view=openxml-3.0.1)。

新解析器版本为 `document-review-studio-docx-v5`，注释定位标记为 `note-stories-v1`。
注释块保留原有 paragraph、heading、table 和 table_cell 类型；`attrs.docx_story`
记录 kind、id、part，段落序号属于该条注释，而非正文。脚注和尾注可使用相同 ID。
ID 按整数语义核对，不将它当作排版后的显示编号，也不编造注释页码。

`attrs.note_references` 记录种类、来源 ID、出现次数和注释入口 `block_id`。
同一段的重复引用汇总计数；注释的其余段落由同一 story 归属识别，不在每个引用中
展开整份注释的块列表，避免多次引用长注释使 IR 和请求成倍膨胀。修改稿重建当前入口。

正文和已有页眉页脚保持原来生成 ID 的顺序，注释附加在其后。旧项目、旧请求和原始
字节不自动重写；重新解析为新项目才能获得本版注释提取。

## 可见性与协议

按主文档的内部关系读取注释，包括非默认路径。外部注释关系不联网读取；包外路径、
不安全目标、重复关系、重复或无效条目标识拒绝生成不可靠映射。没有明确关系但常用
路径存在注释时，保留可读内容并产生高风险归属提示，需要核对原件。

缺失的注释条目单独列出；未被正文引用的条目也保留并标记。公式、嵌入内容和不支持
的结构沿用可见性警告，未接受修订继续受既有质量门约束。读取到注释不等于提取了
Word 的全部内容；批注语义仍属于既有警告范围。注释不能替代正文越过空稿质量门。

保存的审查协议携带 `note_visibility`，说明条目、引用、缺失项、关系来源及实际读取
状态。位置契约要求核对相关注释中的限定与出处，区分作者说明与引用来源；读到文献
题录或引文不等于独立核实了文献及其支持范围。这些信息随请求快照绑定，不追改旧协议。

## 阅读与修改

繁中、英文的预览和原文面板都显示注释种类及来源标识。正文引用可跳到注释，注释可
返回引用段落；相冲突的搜索会清除以显示目标。注释目录独立于文章章节目录。

Word 净稿和原生修订副本支持注释中的普通段内替换，保留引用标记、标记样式与未修改
的其他包部件。注释段落拆分的新增段落仍属于原注释；普通注释表格使用既有单元格修改
规则。保格式导出重新读取实际原件，不仅依赖 IR 的可见性字段。

独立检查还复现了段落属性中的制表位被当作正文字符的问题：原位替换可能错移文字。
现将段落、文字、表格等格式属性排除在文本遍历之外，同时保留正文中真正的制表符。
净稿与修订接受/拒绝的文字逐字核对，并检查制表位设置仍在原处。

正文段内替换可保留未被跨越的注释标记。若改变跨过引用位置，或拆分含正文引用的
段落，应用不能确认引用应附着于哪项新表述，原位输出会说明限制，要求人工核对。
保留的标记不证明语义指向正确。范围替换不能跨越正文和不同注释。

注释段落删除保留必要的注释标记结构。规范化 Markdown 以明确的注释标题和段落级
来源 ID 说明关系，不声称复原了 Word 的行内标记位置、显示编号或原始注释版式。

## 验证范围

拥有的合成夹具覆盖八种语言、多段与空段落、相同脚注/尾注 ID、注释表格、自定义
部件路径、重复引用、缺失项、不安全或外部关系、歧义引用与资源上限。
标准 XML 读取器独立检查净稿和修订副本中接受/拒绝后的文字、标记数量、样式及其他
ZIP 部件逐字节不变，避免只依赖同一解析器往返验证。

完整项目验收包含真实 Action/Hunk 人工批准、注释拆分及正式导出。浏览器验证双语
预览、320宽度与桌面布局、键盘双向跳转、搜索清除、已保存的三个学术协议和原件不变。
发行自检新增 `docx-notes`，合计35项。合成响应和检查不作为模型准确率或独立作者试用
的证明，也没有替用户把未知的外部来源认证为真实。
