# 0.2.34：在构造 XML 树时执行结构预算

此前，ZIP 解压体积与正文块数量已有上限，但 XML 会先构造整棵树，再进入正文检查。
Office 适配器的嵌套检查也在树构造之后。小型对照中，公共 XML 读取器能够直接构造
300层嵌套树；这项检查没有覆盖树构造阶段。

现在公共读取器在追加下一个元素之前检查预算，因此 Word、Excel、PowerPoint、
ODT及共用读取器的 Word 导出路径都具备这项保护。原有 DTD/实体拒绝、ZIP 解压体积、
压缩比与正文容量限制保留。Office 命名空间归一化无需再构造带深度计数的遍历列表。

## 默认边界

| 参数 | 默认值 | 计算范围 |
| --- | ---: | --- |
| `max_xml_elements` | 1,000,000 | 每次解析单个 XML 部件的元素数量 |
| `max_xml_total_elements` | 2,000,000 | 同一个已验证 ZIP 对象中的累计解析元素数量 |
| `max_xml_depth` | 128 | 根元素深度为0，允许最大深度128 |

总预算会计算辅助部件以及同一部件的重复解析；它限制实际解析工作量，而非只计算
ZIP 中唯一部件的数量。缺失的可选部件不消耗预算；失败解析已经消耗的预算不返还。
新的导入对象拥有独立预算，不使用跨操作缓存，也不因前次失败限制后续正常导入。
旧式 Python 调用若没有新增的 XML 限制字段，仍使用安全默认值。
显式限额必须为非负整数；布尔值、非有限数值或其他类型不能悄悄停用检查。

这些是结构与工作量限制，并非对实际内存占用作精确测量。特别复杂的正常文件也可能
达到上限；应拆分、简化或选择更适合内容的导入格式，而不是静默丢弃剩余内容。

## 失败与恢复

超限按识别错误处理：完整上传字节和诊断保留，项目显示识别受阻，没有部分内部文档，
也不能直接确认或生成审查请求。浏览器用繁中、英文给出拆分或简化后重新导入的指引。
只翻译完整匹配的已知系统诊断；包含用户文字的未知诊断保持原样，并作为普通文字显示。
作者仍可返回项目库导入其他文件，原失败项目不被覆盖。

## 验证

测试覆盖元素和深度的精确边界、同级元素不累计深度、停止前已构造的元素数量、
跨部件和重复读取的总预算、失败解析不返还预算、独立导入不受前次失败影响。
真实 ZIP/XML 夹具覆盖 Word、Excel、PowerPoint、ODT及既有八语言与 Word 保真导出。
对照确认正常解析结果保持一致；限额失败保留原件且不产生部分正文。

浏览器用小预算触发真实失败路径，避免在测试机上制造资源耗尽。核对繁中桌面、
英文320宽度、未知诊断HTML惰性、返回与重新导入，以及原件字节不变。
发行自检覆盖三类 XML 限额及失败后的新项目导入。存储和模型响应契约不变，
历史识别记录不自动重写；本版不宣称已经完成全面安全认证。
