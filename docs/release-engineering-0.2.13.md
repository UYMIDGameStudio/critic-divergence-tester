# 0.2.13 · 文本结构容量与长单元格内存

此前 Markdown 没有执行表格行、列与总单元格限制，纯文本也可以用大量短行生成
过量结构化对象。现在先检查原始行数，再拆分文本；每次构建文本块或表格之前，
检查整个文档与当前表格的剩余额度。多张表格共享单元格和文本块额度。

默认上限为 250,000 原始行、50,000 结构化块（含表格容器和单元格），以及
50,000 表格单元格；单表最多 10,000 行、单行最多 1,000 列。
空行和代码围栏内的行计入原始行额度，但普通竖线文字及围栏内容不会被当成表格
单元格计数。触及上限仍可完整解析，超过才拒绝；失败项目保留原件、诊断与完整性
记录，不发布截断的 IR。

表格行解析改为按转义符与分隔符分段读取，不再为每个字符创建列表元素。
本机以 300,004 字符的合成中文单元格比较 0.2.12 和本版，单元格结果完全一致；
`tracemalloc` 测得峰值分别为 21,801,656 与 2,102,453 字节。
这是特定合成样本的解析器测量，不是整个应用的内存或速度保证。

回归覆盖边界、超限前停止构建、混合换行、空行、围栏、跨表累计，以及失败项目
原件保留；继续验证 Markdown 内容往返、原文位置、多语言与 Office 导入兼容。
产品仍为 experimental preview。
