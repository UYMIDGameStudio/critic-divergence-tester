# 0.2.40：导出报告的文字边界

## 问题与范围

网页已将原文与模型意见转义，但此前部分 Markdown 报告直接插入原文摘录、模型结论、
最强辩护、综评、模型名称或人工决定。在允许原始 HTML 的预览器中，这些字段可能形成
活动 HTML 或远程图片；Markdown 字段也可能插入图片、链接或伪造章节。

本版将这些自由文字按 CommonMark 的文字规则编码。涉及 AI 审查报告、正式 audit.md、
细读与综评区、对抗审查区、修改任务 findings-report.md、未解决风险报告，以及 Word
导出说明。模板自己的标题和列表继续使用 Markdown，外来文字不取得模板控制权。

实现依据为 [CommonMark 0.31.2 的反斜杠转义、字符引用及原始 HTML 规则](https://spec.commonmark.org/0.31.2/)。
使用标准库进行字符编码，不新增应用运行时依赖。普通 ID、数值和带连字符的词保持
原本写法；转义后的 Markdown 在预览中显示为原文字，源码中可能出现反斜杠和实体。
报告显示统一 CRLF/CR；原始字节与记录不做这种转换。

## 差异与历史

旧差异报告使用固定代码围栏。原文未修改的代码围栏会带一个差异上下文前缀空格，仍可能
关闭外层围栏。本版改用逐行缩进代码块，使原文中的代码围栏和 HTML 始终属于差异文字。
同时为没有末尾换行的差异行补上标准说明，避免前后两行粘连成一行。

新 AI 快照、AI 导出清单、正式 audit.json 与修改任务绑定记录写入
report_rendering_version=1。修改任务的派生 ID 纳入报告格式版本，避免继续命中旧格式
缓存；相同决定重复生成新版任务仍保持幂等。已有决定、计划、Hunk 与 Revision 不重判。

正式导出从绑定的本轮原文和已批准修改稿重新生成差异报告，不再直接复制旧 Revision
中的差异 Markdown。历史 Revision 和旧任务报告保持原字节及原收据，供追溯；新旧报告
可以共存。已保存的旧文件不会自动变成新版格式，使用者需要重新导出新报告。

## 保留原始材料

这是审查报告的呈现边界，不是对稿件正文的清洗。源文件、IR、模型原始响应、Finding、
原 AuditRun、人工理由与已批准修改稿仍保留原文；JSON 导出中的这些内容也保持原值。
模型请求、原始材料和历史报告是追溯证据，不能把整个证据 ZIP 内的每个 Markdown 文件
都当作新版可预览报告。外部预览器的扩展、插件或主动执行代码不在本次验收范围内。

## 验证

测试通过真实项目导入模型结果，完成对抗辩护和复核、人工修正、修改任务、Hunk 批准、
Revision、外部复审和正式导出，另覆盖零 Finding 的学术综评。模型响应和源文件在流程前后
按字节比对，检查结构化意见未被显示层改写。

历史兼容样例用真实追溯写入流程一次性创建旧格式任务与旧差异报告，不篡改既有文件、
收据或完整性索引。新版生成不同任务路径、复用新的格式缓存，正式导出重新渲染差异，
同时核对历史字节未变。

仅开发验收增加固定版本 commonmark.js 参考解析器。关闭其安全过滤，先以原始 HTML
作阳性对照，再解析9份真实报告及1份文字往返样例；确认语法树无活动 HTML、图片或链接，
攻击标题没有变成真实标题。浏览器在1440与320宽度检查原文字、八种语言、文件名、字面
代码、无脚本执行、无外部请求及无横向溢出。依据为
[参考实现的 Parser、HtmlRenderer 和 safe 选项](https://github.com/commonmark/commonmark.js#usage)。

安装运行时自检增加 report-literal-text，合计33项。以上证据验证程序呈现与追溯边界，
不代表模型准确率提高，也不替代真实作者试用或发行者代码签名。
