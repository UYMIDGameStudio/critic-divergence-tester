# 0.2.45：解析结果预算与草稿回显

## 已复现的问题

上传大小、ZIP 展开大小、XML 元素及文本块上限不能直接限制最终 IR 的大小。
Word 注释的部件路径会保存在块属性和定位映射中；一个拥有的合成文件约19 KB，
128条注释段落和较长的部件路径生成了约2.2 MB的规范 JSON。更长路径和更多段落
仍可通过原先的文件与块数限制，导致序列化、落盘、页面响应及协议材料放大。
复现记录在本机 `dist/ir-amplification-before.log`，不是普通论文的一般膨胀率。

## 统一解析结果预算

`IngestionLimits.max_ir_json_bytes` 默认64 MiB，追加在既有字段后，保留旧的位置参数
含义。所有 `ingest_bytes()` 路由在返回结构化文档前，检查同一份 JSON 大小预算，
包括文本、Word、PDF/OCR、现代 Office 及旧格式转换结果。已有字节、XML、表格、
行数和正文质量门继续独立执行，解析结果不截断为一个看似成功的部分文档。

计量对应现有规范 JSON 的 UTF-8 字节：紧凑分隔符、非 ASCII 原文、控制字符和
引号/反斜线转义、有限数字及末尾换行均计入。只读遍历不改写文字、坐标、属性或
已接受结果的哈希。内部 JSON 的计量编码不限制上传文件的原始编码或语言。

计量不会先生成完整 JSON 字符串。字符串分块检查，每块最多8192个字符；结构用迭代器
遍历，避免遍历栈随整个数组长度扩大。共享字符串测量结果可复用，每个输出位置仍独立
计费，防止重复属性被少算。出现环、无效 Unicode、非有限数字或非 JSON 数据时拒绝。

超限在解析器结果写入前产生明确诊断。新项目保留完整上传字节及失败记录，没有部分
`document.json`、质量报告或定位映射进入正式审查。失败重试保留原有项目状态；作者
可返回项目库并导入拆分后的文件。历史项目和已有协议不自动重写，重新解析为新项目
才应用新的解析预算。预算针对解析器返回的 IR，不是整个项目、导出包或所有进程内存
的总上限，也不取代后续材料的独立限额。

## 草稿保存后的回显

浏览器验收发现，保存成功后只更新了活动草稿对象，页面缓存仍携带旧版本；失败操作
没有获取新视图时，切换语言可能用旧缓存重新初始化草稿，误报「另一页面已保存」。

保存确认现在同步对应页面快照中的已保存字段、滚动位置和版本。仅接受当前项目与
文档范围的确认；不覆盖较新的服务端视图、只读诊断或后来尚未保存的输入。服务器
仍严格检查草稿版本，真正的旧页面写入继续返回409。已知草稿错误保存原始系统标识，
繁中/英文切换时重新显示；未知错误和文稿内容保持原文。

## 验证

计量测试对照实际规范 JSON，覆盖边界、控制字符、分块交界、八种语言、补充平面字符、
共享对象、循环及无效数据；转义膨胀检查同时测量额外内存，验证不会分配完整转义结果。
11条实际格式路由在准确边界接受，在少一字节时拒绝，并逐字节比较被接受结果。

真实默认预算夹具用不足100 KB的原件触发超限，不生成巨型 JSON。核对原件、状态、
完整性、重试原子性以及旧项目在另行解析失败后不变。浏览器覆盖繁中桌面/英文320宽度、
无部分审查入口、失败重试、干净草稿确认后的语言切换、真实跨页冲突及新文件恢复。

发行自检新增 `ir-budget`，共37项；新的计量模块进入 wheel 和便携包，隔离安装继续
检查实际模块来源。运行时与浏览器验收分别记录，不以这些安全检查代替模型准确率评测。
