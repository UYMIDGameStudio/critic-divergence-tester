# 0.2.25：重新解析、核验来源与审查材料边界

本版继续 [0.2.24 的本机实例检查](release-engineering-0.2.24.md)，补查存档审查意见，
并修复重新导入与审查证据呈现的问题。私有正文、文件名、路径、引文和模型回复
不进入公开仓库；回归用例使用合成文件。此检查不替代作者试用或学术准确率评测。

已完成全部 8 个项目、28 份模型审查及 93 条意见的逐项复核，范围和分类边界见
[匿名全量检查记录](local-project-review-20260927.md)。

## 修复

1. **可以真正重新解析同一原件。** 普通重复上传原先会直接打开旧项目，因而
   仅“重新导入”不能让旧 PDF 获得新的解析结果。现在导入页提供
   「重新解析為新專案（保留舊專案與審查記錄）」选项；English 界面提供相同功能。
   勾选后创建独立目录、项目标识与未确认的识别结果，使用当前解析器重新处理原件。
   自动名称加序号；明确输入的标题保持原样。旧审查、人工决定和修订不复制到新项目，
   也不改写。未勾选时保留普通重复上传行为。此选项同样支持 Word 等其他格式。
2. **明确谁声明“已核实”。** 实例中有模型意见返回 `verified`，但没有应用
   独立核验外部材料的记录。现在界面、两类 Markdown 报告与 JSON 导出附加来源说明：
   模型声明已核实，不表示应用已核验外部事实；已检查引句格式也不等于判断正确。
   来源按所属审查运行判定，历史本地规则即使误写 `model-derived` 也不会误当模型。
   今后本地规则明确记录为 `rule-derived`。存档枚举、原始响应和完整性凭据不变。
3. **把实际提取限制传给审查者。** 某些 Word 原件包含未纳入正文的脚注，界面
   有提示，旧导出协议却只带正文块。新请求增加解析器、实际警告、质量信号和图片
   占位数量。涉及不可见材料的批评必须说明范围、待检查材料与适用条件，不能把
   “没有提取到”直接断言成“原稿没有”。已有可见段落充分支持的批评仍可提出。
   新提示由既有摘要绑定；保存过的提示不会追溯改写。
4. **保留历史细读边界。** 未提供上下文反证核对的模型意见在界面及导出报告中
   明确提示检查作者是否已在其他段落回答。本地规则不会被误加这项模型提示。

## 验证边界

针对新导入路径验证了默认重复上传、连续建立两个新项目、严格布尔参数、原稿摘要、
旧目录全部文件字节不变、审查状态重置，以及真实 PDF 文字对象夹具重新获得布局提取。
核验来源覆盖模型、本地、历史错误标签及来源未知的情况，并核对导出与存档分离。
脚注用例确认实际遗漏警告进入保存的提示，纯文本对照不会凭空产生遗漏警告。
发行自检增加新项目导入检查，继续检查 PDF 恢复及学术协议。

旧意见中的过严标准、相关重复任务和外部事实争议仍需逐项人工裁决。既有学术协议 v2
要求按文章任务选择标准；本轮没有让模型按 v2 重跑全部私有文章，不能将旧意见的
复核结果换算成新版准确率。仍未完成未参与开发的作者对照试用。

## 使用

完整解压新版发行包后启动；旧程序不会自动取得修复。需要更新审查输入时，在
新稿审查页选原文件、勾选上述选项、开始识别，并重新确认识别与用途。需要保留
旧轮次进行比较时，直接在本地项目列表打开旧项目。安装及回退方式见
[便携版说明](portable-guide.md)。
