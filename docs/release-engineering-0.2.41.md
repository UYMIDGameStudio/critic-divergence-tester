# 0.2.41：长文复审的可还原段落引用

## 实际问题

旧复审请求同时包含原协议全文、单独的 critic 定义、带有定义副本的来源绑定，以及完整
修订稿。长文的重复正文和重复标准占用上下文，也容易混淆历史材料与当前引文来源。

本版去掉协议定义的两份重复展示，保留原请求中完整的标准、上下文、细读和综评协议。
更改的是复审输入的组织方式；响应中的 resolutions、new_findings 与引文核对规则不变。

## 可还原引用

仅在历史段落与本轮段落的整个 JSON 对象相同时，以 same_as_current 引用本轮对应块。
比较包括块标识、文本、层级、位置、属性与子块顺序，不是只看编号、文字相似度或归一化
引文。布尔与数字、整数与浮点数、组合与预组合 Unicode 文字都不能因宽松相等而误复用。

不相同或已删除的历史块以 historical_block 完整保留，全部历史块的顺序不变。本轮完整
blocks 数组仍在协议末段。用本轮对象替换引用即可逐块还原原请求提供的旧稿数据，不需要
模型猜测缺失内容，也不靠挑段落、概要、字符截断或只保留主要问题节省长度。

历史 document JSON 以外的原请求文字保持逐字不变，包括额外政策、上下文说明与响应
示例。旧请求编号、模型声明及响应例属于历史记录，新增说明明确要求使用本次末尾的
Required response envelope，不把历史块作为修订稿引文。

重组只保证 JSON 数据值的还原，不声称投影中的 JSON 空白与转义写法等于原文件字节。
原始 prompt 文件仍以原字节保留并绑定 SHA-256。不能安全识别的旧布局、重复字段、
歧义块编号或不能精确保留的数字写法，均保留完整原 prompt。全部段落变化或重组不更短
时也使用原文，saved_bytes=0，不伪称已经节省请求体积。

## 协议与版本绑定

新外部复审请求 schema_version=4，historical_prompt_projection.version=1。记录原文件
摘要、投影摘要、历史与当前 blocks 摘要、块数、复用数及真实 UTF-8 字节差；不估算 token。
revised_document_sha256 绑定完整的本轮 IR，既有 revised_sha256 继续绑定修改稿。

读取和导入前从原始文件重新生成预期投影，检查元数据和模型可见内容逐字一致，并核对
本轮全文确实等于绑定 IR 的全部 blocks。原标准被改写、引用指向不同数据、当前正文
缺失、摘要失配、字段缺失或未知版本，都会拒绝继续；不能只凭调用者提供的摘要通过。
同一读取操作共用本轮 IR，缓存不跨项目或后续操作保留。

已有1至3版请求继续按原格式读取，不自动改写。未知请求版本拒绝处理。旧应用不能导入
4版请求，应使用本版或支持该版本的更新应用；原响应协议版本及项目 IR 格式不因此改号。
下一轮仍绑定其原 critic 快照，引用目标会重新核对新的本轮 IR，不沿用前一轮的投影。

## 验证与边界

纯数据测试覆盖删除、增加、改序、位置与属性差异、JSON 类型差异、八种语言、Unicode
等价但不同的字面形式、重复编号、重复字段、非规范数字及旧布局回退。真实项目覆盖
长文、跨轮复审、无法复用的短文、当前引文导入，以及拥有一致收据但投影内容有误的
新建测试项目。拒绝后不发布结果，原记录字节保持不变。

浏览器从真实下载的协议重建全部旧 blocks，并与原请求逐块比较；同时对照完整本轮 IR，
核对繁中桌面与英文320宽度说明、无横向溢出、无脚本错误及无外部请求。

合成90段长文的该次测量：历史 prompt 部分从93,032字节变为16,078字节，减少76,954
字节；90块复用、1块保留为完整旧记录，整个本次复审请求为104,950字节。这里只报告
真实 UTF-8 长度，不是模型 token、费用、延迟或审查准确率测试，也不能外推所有稿件。

运行时自检增加 lossless-recheck-source，合计34项。此优化不证明提取完整、模型理解了
全部材料或批评成立；人工决定及真实作者试用要求仍保留。
