# Gate C 实际试用执行包

本材料供组织者记录真实试用，不是参与者已完成的证据。
受测版本：0.2.2 候选版；开始前填入实际 ZIP 摘要和设备信息。
正式判定仍使用 [Gate C 原标准](gate-c-usability-report.md)，不降低人数、任务或记录要求。

## 组织与材料

安排 3–5 位未参与开发的目标作者。每人使用有权处理的真实稿件和已有审查报告，
准备两个工作量接近的任务；记录它们在篇幅、问题数量、熟悉程度上的差别。
本轮已有报告修稿入口接收 Markdown/TXT 稿件；如作者原稿是 Word，应在计时前说明
需要准备文本副本，并单独记录准备时间和由此带来的负担，不能隐去这一步。
如果该限制导致作者不能完成，也应记为结果，不能替其悄悄转换后称无帮助完成。

使用 P1–P5 等代号。只保留作者明确同意保存的原稿、屏幕、操作记录和脱敏引用；
不同意保存材料不等于同意上传给外部模型。沿用作者自行选择且认可的模型服务。
组织者不得代做裁决、填写理由或编辑模型 JSON；任何指导都记录时间与具体内容。

## 给作者的任务文字

繁體中文：

> 請根據你已有的審查報告修改這份稿件。你可以接受、拒絕或暫緩任何意見，
> 最終保留你認可的版本。完成後，請說明哪些地方改了、為何要改，以及哪些問題
> 仍未解決。若無法完成，可以隨時停止並說明遇到的困難。

English:

> Revise this manuscript using your existing review report. You may accept,
> reject, or defer any comment. Keep a final version you agree with. When done,
> explain what changed, why it changed, and what remains unresolved. You may
> stop at any point and describe what prevented you from continuing.

直接 AI 任务：由作者把原稿及报告交给其选择的 AI，要求修改；作者按日常方式检查结果。
工作台任务：打开发行版默认首页，仅使用可见提示找到已有报告修稿流程。
不给作者 README、隐藏 URL、实现术语清单或 JSON 编辑指导。
组织者事先核对安装和启动是否可用；安装准备与任务时间分开保存。

## 每个任务的记录页（逐任务复制）

- 参与者代号、任务代号、路径（直接 AI／工作台）：待记录。
- 稿件、报告、最终稿及允许保存证据的位置和摘要：待记录。
- 开始、完成／退出时间，包含时区：待记录。
- 活跃操作区间、等待模型区间、暂停区间：待记录；不以端到端减去估计值冒充活跃时间。
- 完成结果：待记录（无帮助完成／接受帮助后完成／未完成）。
- 模型回传修复次数，以及修复原因：待记录。
- Finding 接受／拒绝／暂缓数量：待记录；不要求人为凑齐各类。
- Hunk 批准／拒绝／编辑后批准数量：待记录。
- V2 修改数量、作者实际查看的修改及未解决项：待记录。
- 作者能否解释“原问题→选择→具体修改→复查结果”，附经同意的原话：待记录。
- 再使用意愿、相对直接 AI 的额外成本是否值得、理由：待记录。

## 汇总与判定

将真实记录填入原 Gate C 表，链接每人的两项任务与困难记录。缺失项注明原因，
不要补估计值或把自动化测试写入参与者行。所有完成及未完成案例都保留。
产品负责人根据原标准追加 pass／fail／defer、日期、理由及仍保留的限制。
作者本人 Gate A/B、独立 Gate A/B 和 Gate C 分别记录，不能互相代替。
即便多人顺利完成，也需单独保留历史大队列负担、复杂格式和 OCR 错误的证据。

当前参与者、时间、任务与结果均**尚未记录**，本执行包不构成通过结论。
