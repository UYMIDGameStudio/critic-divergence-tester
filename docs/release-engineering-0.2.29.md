# 0.2.29：按文章问题选择角度的综合审查

以往协议主要检验支持链、概念边界、反例与证据强度。文章即使没有可定位的
逻辑错误，其组织、研究方向、方法组合和表达手法仍可能值得分析和调整。
本版把这些设计判断作为独立成果显示，而不是将所有评价强行变成 Finding。

## 审查角度从哪里开始

| 维度 | 描述与评价任务 | 可以成立的正向判断 |
| --- | --- | --- |
| 结构 | 中心问题、主次论证、章节任务、推进顺序、篇幅重心、铺垫与结论收束 | 先展示竞争解释，再作区分，使后续推导更容易跟上；可建议保留 |
| 方向 | 从什么起点朝什么目标推进，解释、批判、辩护、问题重设或方案建构如何转换 | 内在批判的路线完成了其自定目标，即使没有提出替代理论 |
| 方法 | 实际论证动作为何适合问题，如何组合，以及转换时的说明责任 | 概念分析与对照异例互相配合，不要求为此增加无关实验 |
| 特征特点 | 可定位的反复手法、关系界定、多声回应、分层限定、修辞压缩的作用和取舍 | 压缩提高传播效率，但某些证明需展开；这项取舍可讨论而非自动判错 |

方向按文章的问题与读者需要判断，不以评审者的思想立场决定正误。方法并不等于
统计或实验设计。特点须有原文实例，只有一处实例时不能冒称全文重复；未检索
外部文献时不能宣称作者独创。这些角度只是起点，还可扩展到问题设定、贡献、前提、证据组织、反驳策略、综合增量、论证经济性、读者效果或实践转化。每个角度都须说明为何影响本文，允许指出有效选择或材料不足。

## 请求、结果与展示

学术协议 v4 沿用三个 critic ID。`academic_argument` 负责一次按稿件任务选择角度的综合审查，
`academic_methods` 深查方法与研究设计，`academic_citations` 深查引用归属；
避免同一篇原稿被要求重复填写三份全文设计表。

新的学术论证响应增加 `argument_assessment`，版本1。先用 `review_frame` 记录实际问题、意图贡献、整体路线、审查重点、范围限制和原文依据。
再用 `dimensions` 保存所选角度；`id`、`title` 和 `why_relevant` 标明角度及其适用理由。
角度无需局限于示例，通常挑3至6个承重角度，系统允许1至10个以控制篇幅，不设填满要求。每项还包含：

- `description`：实际选择与路线。
- `assessment`、`status`：其作用与取舍；状态为 effective、mixed、weak 或 unable-to-assess。
- `strengths`、`limitations`：最多各3项，可以为空。
- `recommendation`：有依据的保留或调整建议。
- `evidence`：最多4条当前稿件的原语言连续引句；只有材料不足状态允许空数组。

文本和条目数量有上限；不要求重复原文全文或提交私有思维过程。状态是模型的
设计判断，不是总分或文章正确性认证。应用核对引句的位置与文字，不代替人工
判断这些评价是否恰当。

综评被保存于对应 AuditRun，在工作台以繁中／英文标题显示，并进入审查快照及
正式审计导出。模型文字与原文不随界面翻译，模型HTML作为普通文字显示。
即使 `findings=[]`，综评仍须提交并可以导出。具体可独立处理的缺陷继续使用
原 Finding 契约及人工裁决流程；综评本身不会自动修改文章。

社会科学、自然科学与工程的 Markdown 专业协议同步在现有第三节选择相关的设计和效果角度，
保留六节输出结构，按各自任务选择具体方法，不为形式完整强制制造错误。

## 历史与使用

协议对象、字段版本及指纹与请求绑定。旧v3及更早请求没有综评要求，可以继续
按原契约导入；不会把新字段追溯套到旧结果。没有绑定综评协议的请求不接受
一个额外综评作为已绑定成果。对抗深审和修订复查仍使用原始标准。
IR 抽取v3及历史定向检查提示词保持各自原有协议版本。

升级到此版后，重新生成学术论证请求，按照其新响应模板导入结果。已经保存的
旧结果不会自动变成新版综合审查，也不会因界面升级被重新评判。

## 验证范围

合成稿件测试覆盖：零 Finding 的综合评价、保存和重载、原文引句校验、无角度、重复角度、无适用理由和跨项目定位拒绝、材料不足、字段上限、协议指纹、旧请求兼容、其他 critic 边界、
审查导出及复审快照。浏览器检查覆盖繁中和英文、桌面／390／320宽度、自定义角度及零 Finding 显示、原文展开、模型文字保留与HTML惰性。

这些是契约和流程回归，不是模型对真实稿件的评审成绩。设计判断的准确性及其
对修稿的帮助，仍需实际稿件与作者评价。
