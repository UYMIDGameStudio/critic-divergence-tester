# 0.2.32：绑定页面所见的审查状态

## 已复现的问题

旧页面只携带原文版本。另一页面在同一稿件上作出新决定后，旧页面仍能提交相反决定，
成为当前决定。两次操作虽都会归档，后一次却没有经过查看最新状态的确认。
草稿版本有时会先阻止提交，但当草稿未改变时，这项保护不足以覆盖审查决定。

## 提交与恢复

页面现在携带本机服务签发的审查状态绑定，覆盖当前项目的完整性索引。正式提交在
项目锁内重新核对；旧状态返回409，保留页面内容和当前输入，不写决定或操作回执。
查看状态与签发绑定同样处于项目锁内，避免命令行写入夹在两者之间。

草稿和界面语言独立保存，不改变审查绑定。返回项目库、备份、恢复、删除和打开
导出文件夹不要求当前审查状态；这些操作仍保留原有项目边界与备份约束。
新增受跟踪记录会改变绑定；这是一项保守的并发保护，不代表每项变化都改变文章含义。

已提交的同一操作编号与原始内容可在旧绑定下重放；先核对回执，再核对当前状态，
不重复执行。即使随后出现新决定，旧操作重放也不会把旧决定重新应用一次。
更换绑定或内容后复用同一操作编号仍被拒绝。

有些无效模型响应会作为错误尝试归档。这类已提交的拒绝记录返回自己的新绑定，
浏览器保留输入供修正后重试。绑定在同一项目锁内取得，不会把另一作者操作悄悄
授权给旧页面。普通冲突不返回新绑定，也不通过自动刷新替用户接受新状态。

## 启动与兼容

加载初始状态前切换语言曾会触发空状态错误。现在先更新标题和偏好，待状态返回后
再绘制工作区；用户的明确选择不会被较晚返回的旧语言设置覆盖。

浏览器的正式操作请求新增必需的 `review_context`；旧页面需要重新加载一次。
直接Python领域调用保持原有方式，也可显式要求绑定。项目、学术综评、IR及模型响应
的存储契约不变，不需要重写历史记录。审查绑定不替代本机令牌和同源访问检查。

## 验证范围

合成项目覆盖：原文与草稿均不变的旧裁决、两个同时提交的决定、不同服务会话、
缺失或畸形绑定、重新核对后的明确新决定、已提交回执重放、错误归档后的修正导入。
核对冲突前后的项目文件字节，确认拒绝没有留下额外决定或回执。

浏览器在繁中和英文下验证：没有草稿写入冲突时仍拒绝旧裁决，原输入保留，重新
加载后可见最新状态；延迟初始响应时可选择语言且不会被覆盖。既有修订、对抗深审、
错误修正和断线重试流程继续回归。发行自检包含旧裁决拒绝及回执不重复执行。

测试不调用外部模型、不读取真实用户稿件；这些结果验证流程保护，不证明审查准确率。
安装和升级见 [便携版说明](portable-guide.md)。
