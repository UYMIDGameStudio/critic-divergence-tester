# 0.2.47：识别恢复与修正草稿

识别失败时，流程的「继续」原先定位到空白的正文预览。拥有的空表格夹具在真实浏览器中
复现了这一行为。现在失败或没有可审查正文的项目提供命名的恢复区域，显示可用操作。
「继续」会进入恢复区域；正常识别结果仍进入原文预览，已打开的修正框则优先取得焦点。
导航在点击时重新查找目标，避免编辑器展开、收起后仍沿用旧位置，并跳过隐藏或禁用目标。

修正编辑器有可访问的文字标签和完整正文说明，打开后焦点进入输入区。打开、提交、收起
使用独立按钮；收起不删除已输入内容，也不会提交识别决定。现有文档范围内的草稿同时保存
文字与展开状态，刷新或切换繁中/英文后恢复；旧版只有修正文字的草稿仍可打开查阅。
明确保存的收起状态优先于自动展开。恢复页面不会自动提交正文、上下文或审查决定。

空正文、纯格式字符、图片占位及辅助内容仍受原有质量门约束；没有可用解析结果时不显示
修正输入入口。已有历史记录的空正文项目不允许覆盖旧审查来源，改为查阅已保存的任务、
协议和既有导出，并另行导入正文。新的查阅区域不提供生成、导入 AI 审查或执行预检的按钮。
后台的质量门、草稿版本冲突与来源绑定规则继续独立执行。

浏览器验收覆盖失败恢复、正常预览、编辑器键盘焦点、繁中桌面与英文320宽度、八种语言及
带标记的原样草稿、刷新和收起后的恢复、无效正文拒绝、真实修正到审查与修改导出全程。
历史夹具通过旧行为建立有效请求与导出记录，再验证当前页面只能查阅，并逐文件比较另行
导入前后的旧项目记录（界面草稿除外）。所有材料均为拥有的合成内容，无模型调用。

本轮没有更改后台 IR 或审查协议规则。验证以相关后台检查、完整浏览器套件、发行自检及
实际发行文件核对为依据；上一版完整974项回归和远端验收单独记录，不算作本轮重新执行。
