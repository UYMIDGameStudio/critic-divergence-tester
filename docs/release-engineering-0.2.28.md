# 0.2.28：按论证任务审查推理结构

新审查会先还原相关前提、推理桥梁、结论及其限定，再指出具体失效处。
例如，“模型可以相容”只能承担可能性的结论；若作者将它升级为现实必然，
审查应定位这个升级及缺少的依据。若作者仅声称展示一种可能，就不能要求
它已经证明现实必然。修补建议可以是收窄结论，不必要求重做整篇文章。

## 可执行的检查

现有学术协议 v3 增加精简的 `argument_structure` 方法段，按 critic 职责选择：

| 检查 ID | 要检验的推理动作 | 参考论证 |
| --- | --- | --- |
| inferential-task | 区分定义、存在证明、解释与规范辩护；必要/充分、等价与冲突类型；必要或唯一解释才承担排他负担 | A08、A11、A13；P01、P13、P18 |
| refutation-reach | 定位反例击中的量词或前提；反驳对方不自动证明自己，局部失败不自动推翻全文 | M06、M09；A12；D05 |
| shared-premise | 检查对立双方共有预设、分类遗漏与交叉；工作分类不必冒充穷尽证明 | P06、P12 |
| analogy-transfer | 对照原场景、目标场景、成立条件和不迁移属性；原则不自动证明具体措施 | G2；M01、M15；P16 |
| explanation-roles | 分开生成原因、当前功能、维持反馈；共变不自动证明直接因果 | D13、D17、D20 |
| object-proxy-comparison | 分开识别标志、代理指标与对象本身；核对比较尺度和范围 | G3；D03、D07、D08、D21 |
| mechanism-conditions | 检查结构到行动的中介、反向作用、资源条件与失败可能 | G8、G10；M05、M06 |
| voice-and-version | 分开作者、对手、译者、编者及审查者的声音；不将评估回写为作者自认 | G7；M01、M09；P17 |
| qualification-integrity | 强断言与脚注限定共同阅读；分开猜测、证明、引述与独立核验 | M06；P17；D03、D20 |

每项都有 `when`、具体检查与防误判约束。理论、人文、经验及规范论证按实际任务
判断；不会将因果机制、统计指标或某一种哲学立场变成所有文章的门槛。
无法访问的附录或版本标为材料不足，不推断为作者未写。

采用既有 `standard`、`issue`、`consequence` 与细读字段提交简短、可定位的判断：
作者真实立场、最强已有辩护、仍存的失败步骤、相关原文及撤回批评的条件。
不新增模型返回大表，不索取私有推理过程，不把参考示例混作稿件证据。

## IR 与历史兼容

IR 抽取 v3 保留现有响应 schema、节点、关系及分类范围，增强声音归属、
隐含前提、限定及推理连接的抽取要求。章节先后不等于逻辑支持；
作者的真实强断言不能被抽取器悄悄改弱，缺少的桥梁不能被虚构补齐。
旧 v1/v2 抽取提示词仍按原字节重建验证。

研究规则库加强既有问题与失败条件，不增加 check ID，不扩大自动路由数量。
每次运行保留库、计划和提示词的原始快照及哈希。新库会形成新审查记录，
不会改判旧记录。定向审查 v1/v2/v3 的历史提示词渲染保持不变。

主工作台的旧学术协议 v2 及更早请求继续可读取；对抗深审和修订复查继续
使用最初绑定的标准。升级软件后，需准备新的学术审查请求才能使用 v3。
已有研究项目保留旧抽取；新建研究项目或导入新稿件版本时采用抽取 v3。

## 验证与能力边界

回归重点为：新规则实际进入导出请求、按角色选择、嵌套对象隔离、历史协议
保留、旧抽取逐字复现、规则库变更形成新快照，以及安装包中的协议完整性。
合成案例覆盖兼容性和出处，不读取真实用户项目。

可用于后续盲测的对照包括：

- “模型不矛盾，所以现实必然如此”与“模型仅展示一种可能”。
- “制度今天有用，所以最初为此创设”与分别论证起源、效果和反馈。
- “规则相同但结果不同”与同一关系下的互斥断言；前者本身不是逻辑矛盾。
- “来源断言必然，编者提出质疑”与误写为“作者承认并非必然”。
- “X是一种候选解释”与未经竞争解释比较便断言“只有X能够解释”。
- 仅用一处失败推翻全文，与说明该缺口只影响哪一项结论。

上述对照是评测设计，不是模型已答对的成绩。自动检查可验证绑定、路由和文本
契约，不能证明审查准确率或实质洞察已经提高；这仍需独立稿件和人工判断。

安装和升级见 [便携版说明](portable-guide.md)。
